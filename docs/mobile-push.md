# Mobile PWA and Web Push setup

The mobile navigation uses the existing application sidebar. The Push switch is in Settings → Notifications. On iPhone, install Qualify from Safari using **Add to Home Screen**, then enable Push in the installed app. Android can enable it in a supported browser or installed PWA. HTTPS is required outside localhost.

The GitHub Actions Edge Function deploy provisions a persistent VAPID key pair in `/root/qualify-supabase/.env.push` on the self-hosted VPS, injects it into the functions container, and deploys `push-config` with `webhook-inbound`. The frontend fetches the public key from `push-config`, so no Vercel build variable is required. Keep `.env.push` on the VPS across deploys: replacing its key pair invalidates existing device subscriptions. `VITE_VAPID_PUBLIC_KEY` remains an optional override for local development. Deploy the `20261101000000_push_delivery_guards.sql` migration before testing delivery.

Push is sent only for inbound chat messages stored in `chat_messages`. The assigned operator receives it, or the instance owner when no operator is assigned. Delivery checks active company membership and active subscriptions, then records one delivery per message and device. Invalid endpoints are revoked. The notification opens the conversation in its company workspace.
Push follows chat visibility: archived conversations, blocked leads, internal messages, and groups not explicitly registered and visible in the CRM are skipped. Each user can silence a conversation from its actions menu without affecting other operators. The notification title is **Nova mensagem**, followed by the contact name and message preview. The operating system may still display the PWA name as the notification source.
